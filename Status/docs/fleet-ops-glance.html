Local · per-host
c:\fleet_monitor\{host}\
server_status_all.json
This host's full fleet-poll snapshot — what /api/status serves. Not shared; each host only ever reads its own.
Local · per-target
c:\fleet_monitor\{host}\
server_status_{target}.json
One file per FLEET entry (e.g. server_status_imagebeast.json) — the same poll broken out per target machine. Confirmed present under chatworkhorse\; presumably mirrored under amsterdamdesktop\.
Shared · flat root
_sync_monitor\machine_info_{host}.json
_sync_monitor\metrics_history_{host}.json
Windows-writer convention (flat, no subfolder). Six hosts write here: amsterdamdesktop, chatworkhorse, imagebeast, remotews, surface3-gc, travelbeast.
Shared · per-host dir
_sync_monitor\{host}\machine_info_{host}.json
_sync_monitor\{host}\metrics_history_{host}.json
_sync_monitor\{host}\heartbeat_{host}.txt
Mac/Linux satellite-writer convention (own subfolder). Five hosts: chatworkhorseunix, workbenchunix, denniss-2nd-macbook-air, denniss-macbook-air, mathes-mac-mini. The two Ubuntu hosts (Immich boxes) also drop a cron.log here (~1MB, cron-scheduled writer instead of a pgrep/nohup guard).
⚠ Anomaly
metrics_history_denniss-macbook-air-AmsterdamDesktop.json
   ...-AmsterdamDesktop-2.json / -3.json
metrics_history_surface3-gc-AmsterdamDesktop.json
OneDrive sync-conflict copies — OneDrive appends -{computername} (incrementing on repeat) when two clients edit the same file while offline from each other. Accumulating since 06/17 for denniss-macbook-air (now 3 stale copies) — means something on AmsterdamDesktop is also trying to write these two Mac/tablet hosts' history files, colliding with their real writers. Worth tracing what's writing history for hosts other than Amsterdam's own — likely a stale config or leftover test path.
